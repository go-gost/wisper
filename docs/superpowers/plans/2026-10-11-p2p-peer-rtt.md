# p2p 对端 RTT 被动测量与实时显示 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Surface the passive p2p latency that is already measured — per-peer KCP SRTT/RTO and the host↔relay DERP ping RTT — through the wisper API and show it live in the peer rows, the p2p entrypoint detail page and the settings p2p section.

**Architecture:** Zero new probing: the KCP session's SRTT is a by-product of the data path, and the DERP keepalive ping already runs every 30s. The p2p repo gains an RTT sample on its ping/pong and a `Status.RelayRTT` field; wisper maps the (already published, in-process) `PeerDiagnostic.RelayKCP` trio into every JSON face it owns; the Lit UI shows a millisecond number where the path badge already is.

**Tech Stack:** Go (p2p module `github.com/go-gost/p2p`; wisper module `github.com/go-gost/wisper`), Lit/TypeScript (web-src), no new dependencies.

**Spec:** `wisper/docs/superpowers/specs/2026-10-11-p2p-peer-rtt-design.md` — the plan argues from it; executors read both.

## Global Constraints

- Two repos: p2p commands run as `git -C /root/code/go-gost/p2p …` / `cd /root/code/go-gost/p2p && …`; wisper commands as `git -C /root/code/go-gost/wisper …` / `cd /root/code/go-gost/wisper && …`. No go.work tricks: gates run with `GOWORK=off`; local builds/tests may use the root workspace.
- Go test gates are per-package (never `./...` — a wildcard run hangs in this environment).
- Code comments and commit messages in English.
- No push, no tag: the maintainer releases/tags. Final go.mod bump task has the release as its precondition.
- API is additive-only: new JSON fields only; `peerStatsJSON`/`peerDiagnosticJSON` use `,omitempty` tags like their neighbours; `tunnelResponse` uses `,omitempty` like `PeerTransport`.
- Display gate: a number renders only when `kcp_live` (or `relay_connected`) is true and the value is > 0; otherwise the element is absent, never "0ms".
- Branch per repo, created as a pre-flight before the first commit of each: before Task 1 run `git -C /root/code/go-gost/p2p switch -c feat/derp-relay-rtt`; before Task 3 run `git -C /root/code/go-gost/wisper switch -c feat/p2p-peer-rtt` (it inherits the committed spec). Merge/cleanup at the end is the human partner's call.

## Review Focus

- **Peer with no session** (key in the allowlist, no `PeerDiagnostics` entry): the RTT block must be absent, not zero. Pinned by Task 3's table case (missing map key → all-zero) and the UI guard `kcp_live && srtt_ms > 0` (Task 4).
- **Non-p2p object** (plain tun entrypoint, non-p2p tunnel, `opts.Peer == ""`): single-peer fields stay absent. Pinned by Task 3's `peer == ""` table case and `,omitempty`.
- **Sub-millisecond round trip** (loopback LAN peer): must read as a small number, never as "not measured". Pinned by Task 1 storing nanoseconds and asserting `LastRTT() > 0`.
- **Connected relay, not yet measured** (first 30s after dial): doctor says "not measured", not silence. Pinned by Task 2's second doctor test.
- **UI store field-by-field copy** (`applyStats` drops unknown fields): the RTT must ride the 3s poll, not blink. Pinned by Task 4 adding the fields to `entrypoint-store.ts` + the tsc gate; settings polling must stop on `disconnectedCallback` (Task 5).

// peerRTTFields carries the pair-KCP RTT trio out of one peer's diagnostic.
// The single mapping point for the three JSON faces that show it: the peer
// stats row, the identity peer diagnostics and the single-peer tunnel
// response. A missing or dead session reads as all-zero, which the UI hides.
func peerRTTFields(diags map[string]p2p.PeerDiagnostic, peer string) (srtt, rto, rttvar int64, live bool) {

}
